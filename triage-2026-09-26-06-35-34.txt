## 2. Confirmed attacks (true positives)

### A. Heartbleed exploitation — CVE-2014-0160 (highest severity)
- **Attacker → victim:** `175.45.176.2 → 149.171.126.17:7002` (TLS on non-standard port).
- Recon: 74 TLS handshake-burst alerts + 62 non-standard-port alerts (custom SIDs 7600102/7600103 in the raw run).
- **Leak evidence (flows filtered to that IP pair / port 7002):** 5 flows, each ~5 KB to server and **~504 KB returned to client** — the classic 100:1 Heartbleed response asymmetry (~2.5 MB total memory disclosure). Stock `SURICATA 2230012` did **not** fire for this pair; it only fired on a smaller `175.45.176.3 ↔ 149.171.126.18:443` exchange (4.7 KB return).
- **Verdict:** true positive, successful memory exfiltration.

### B. SMB IPC$ compromise + DCE/RPC write — `149.171.126.19:445`
- 128 `GPL NETBIOS SMB-DS IPC$ unicode share access` alerts (SID 2102466), dominated by `175.45.176.0 → 149.171.126.19:445`; plus 18 SID 2100538 alerts from other attackers.
- SMB app-layer events filtered to `dest_ip 149.171.126.19`:
  - `175.45.176.3` ran ~60 `SESSION_SETUP_ANDX` attempts (login brute-force).
  - `175.45.176.0` achieved **`SESSION_SETUP_ANDX` → `STATUS_SUCCESS`**, then **`NT_CREATE_ANDX` of `\alert` → `STATUS_SUCCESS`**, then a **`WRITE_ANDX` carrying a DCERPC request (opnum 23)**.
- **Verdict:** true positive — authenticated SMB/DCERPC post-exploitation against `.19`.

### C. FTP multi-stage attack — `175.45.176.2 → 149.171.126.16:21`
- 36 `GPL FTP PASS overflow attempt` alerts (SID 2101972).
- FTP app-layer events filtered to that pair showed:
  - Anonymous logins (`USER anonymous`, `230` responses).
  - A `MKD` command containing a **NOP-sled (`\x90`…) + shellcode** payload (server replied with null → likely crash/hang).
  - **36 PASS overflow/fuzz attempts**: `%n%n…`, `%s%s…`, `%99999999s`, long `A…A` strings, `../..` traversal strings.
  - **4 successful directory-traversal downloads** (`RETR /../../<dir>/<file>`, replies "Transfer completed") — file exfiltration.
- Related alerts: `FTP USER overflow`, `FTP MKD overflow`, FTP SQL-injection username attempts, `FTP SITE overflow`.
- **Verdict:** true positive — exploit + brute-force + exfiltration.

### D. HTTP IIS Unicode traversal / command execution attempts
- 7 `ET WEB_SERVER cmd.exe In URI` (SID 2009361) and 5 `/system32/` (SID 2009362):
  - `GET /scripts/..%c1%1c..%c1%1c../winnt/system32/cmd.exe?/c dir` style requests against `.12`, `.15`, `.16`.
- Also: XSS in URI, SQLi in URI/body, `/etc/hosts` access, XXE, Apache Struts OGNL RCE probes, HP/Sophos/Zavio exploit probes.
- **Outcome:** no HTTP response status was recorded for the `cmd.exe` URIs (all 7 `http` events were request-only), so command execution could not be confirmed, but the attempts are clearly hostile.
- **Verdict:** true positive attack attempts (success unconfirmed).

### E. Fragmentation overlap — evasion tied to web attacks
- 51 `SURICATA FRAG IPv4 Fragmentation overlap` (SID 2200070); **49 are `175.45.176.0 → 149.171.126.12`** — the same host hit by the `cmd.exe`/`/system32/` web attacks.
- **Verdict:** attacker-induced fragmentation/overlap, consistent with IDS evasion, not benign noise.

### F. TFTP sensitive-file exfiltration and overflow attempts
- TFTP app-layer events (attacker range → servers :69) show:
  - `read shadow` (`.18`), `read passwd` (`.19`), `read boot.ini` (`.10`).
  - `read %.1021x` format-string probe (`.12`).
  - Multiple 256–1400-byte filenames (buffer-overflow attempts) and `write` (Put) uploads with long filenames.
- Stock alerts: `TFTP GET passwd` (4), `TFTP GET shadow` (2), `TFTP Put` (6), `TFTP32 Get Format string` (2).
- **Verdict:** true positive reconnaissance/exfiltration/overflow attempts.

### G. Reconnaissance sweeps (true positives)
- **RPC portmap (rpcbind) sweep** to TCP/UDP 111 across `149.171.126.0/24` — dozens of per-program GPL alerts (`rstatd`, `cachefsd`, `amountd`, `ypserv`, `rexd`, `sadmind`, `rusers`, `mountd`, `NFS`, etc.).
- **SQL port scans:** `ET SCAN … mySQL 3306` (4), `MSSQL 1433` (2), `Oracle 1521` (2).
- **DNS recon:** `DNS zone transfer UDP` (2) to `.14:53`; `DNS named version attempt` (3) to `.15:53`.
- **SNMP probes:** `SNMP public access` (4), `SNMP private access` (2), `Cisco IOS ILMI hidden community` (2) to `:161`.

### H. Suspected shellcode delivery
- `ET SHELLCODE Rothenburg Shellcode` (SID 2009247), 5 alerts:
  - 2 attacker→server to high ports (`175.45.176.0→.16:49188`, `175.45.176.2→.17:33726`) — small closed flows (~1.3 KB in / 364 B out); plausible shellcode probes.
  - 3 `server:80 → attacker` — likely false positives (shellcode byte pattern inside HTTP response bodies).

### I. Internal backdoor shell banner (found during rule validation)

- **Verdict:** strong indicator that `149.171.126.15` is running a backdoor/reverse-shell listener. The stock ruleset does not catch this.

## 5. Coverage gaps identified

1. **Heartbleed leak volume is not directly detectable.** The decisive evidence was 5 flows returning ~504 KB each on port 7002; single-packet rules can't express flow-byte asymmetry. My rules cover the recon/handshake behaviour, but a post-hoc flow-volume detector (e.g., NetFlow/Zeek or a custom Suricata flowbit + byte threshold approach) would be the real fix.
2. **Outbound backdoor shell banner from a HOME_NET host** (`149.171.126.15 → attacker`) was invisible in the raw run because `unsw_triage.rules` was not loaded. It is covered by SID 7600203 for validation runs, but the raw stock ruleset alone would miss this post-compromise signal.
3. **Successful SMB DCERPC write after IPC$ auth** is not specifically detected; current coverage only sees the IPC$ share connect/enumeration (2102466/2100538, 7600202/7600205).
4. **RPC portmap sweeps** were only seen as per-program request alerts; now consolidated by 7600504/7600505.
5. **FTP directory-traversal downloads** were completely invisible to stock rules; now covered by 7600503.
