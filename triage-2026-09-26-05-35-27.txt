# UNSW-NB15 pcap 3 — Triage Report

## 1. Big picture

- **Capture:** `logs/unsw-3-raw/eve.json` (Suricata 8.0.6, 3,555,838 packets, ~1.94 GB)
- **Total alerts:** 893, across **~150 distinct signatures**
- **Activity window:** ~11:01–11:29 local time (2015-02-18), with a large flow peak at 11:20
- **Top event types:** flow 39,768 / dns 35,131 / fileinfo 9,347 / ftp 9,251 / anomaly 8,605 / http 7,566 / smtp 3,294

### Actors
- **Attackers (EXTERNAL_NET):** 175.45.176.0, .1, .2, .3 — the known UNSW attacker range
  - 175.45.176.1: 299 alerts — SMB IPC$, FTP brute force, MySQL brute force, SQLi
  - 175.45.176.0: 181 alerts — broad recon (RPC/TFTP/SNMP/DB), TLS upload, SQL Slammer
  - 175.45.176.2: 180 alerts — DCERPC bind flood, HTTP oversized-request flood, FTP fuzz
  - 175.45.176.3: 97 alerts — RPC/SMB recon, DNS zone transfer, **backdoor access**
- **Victims (HOME_NET servers):** 149.171.126.10–.19, most heavily .15, .18, .19
- Internal→client alerts are mostly parser noise plus one confirmed compromise.

## 2. Signature categorisation

| Category | Examples | Verdict |
|---|---|---|
| Real threats | GPL NETBIOS SMB-DS/IPC$ access (151), GPL DCERPC invalid bind (69), GPL FTP USER overflow (26), ET SCAN MYSQL brute/scan (23), ET WEB_SERVER SQLi, ET SHELLCODE, GPL EXPLOIT cmd.exe banner | True positives / attempts |
| Stale custom rules | CUSTOM TLS heartbeat/handshake burst (7600102, 34), CUSTOM TLS non-standard port (7600103, 32) | **False positives in UNSW** (see §5) |

| Info/hunting | Ask Webcrawler UA, FTP %/quote usage, UPnP response, proxy TRACE | Informational |

## 3. Confirmed attacks

### 3.1 Backdoor + outbound cmd.exe shell — **CONFIRMED COMPROMISE**
- Filter: `alert` events where `(src=149.171.126.13, dst=175.45.176.3)`.
- At **11:19:38**, 149.171.126.13:37726 → 175.45.176.3:63031 sent a Windows cmd.exe banner, matching:
  - ET RETIRED Windows 7 CMD Shell from Local System (2012690)
  - ET ATTACK_RESPONSE Possible MS CMD Shell opened on local system 2 (2018392)
  - GPL EXPLOIT Microsoft cmd.exe banner (2102123)
- Flow evidence: 175.45.176.3:63031 → 149.171.126.13:37726, 8 pkts / 8 pkts, 492 B in / **694 B out**, ~0.5 s. The attacker connected to a **backdoor listener on :37726** and received the shell banner.
- Preceding activity from the same attacker to .13: RPC portmap `sadmind`/`snmpXdmi` requests at 11:05 and 11:18:53 (45 s before the shell).
- **Post-compromise data access:** two large POP3 transfers from .13:110 → .3:
  - `14051 → 110`: 352,012 bytes to client
  - `47330 → 110`: 809,123 bytes to client
  - (No `pop3` app-layer events were logged — see coverage gaps.)
- SMTP abuse: .3 → .13:25 uploaded ~88 KB with a random HELO / MAIL FROM / RCPT TO.

### 3.2 SMB IPC$ share-access burst — recon/access attempt
- Filter: `alert` where `(src=175.45.176.1, dst=149.171.126.15)` → **124** `GPL NETBIOS SMB-DS IPC$ unicode share access`.
- SMB app-layer evidence: **58** `NEGOTIATE_PROTOCOL` (STATUS_SUCCESS) followed by **58** `TREE_CONNECT_ANDX` to `\\149.171.126.15\IPC$` between 11:28:21 and ~11:29.
- Flows were small (~1.2 KB up / ~0.9 KB down), state `closed`; tree-connect response status was not captured (`status=null`), so share access itself is **unconfirmed**, but this is unambiguous SMB enumeration/brute-force behaviour.

### 3.3 DCERPC invalid-bind flood — RPC exploit/recon attempt
- Filter: `alert` where `(src=175.45.176.2, dst=149.171.126.18)` → **69** `GPL NETBIOS DCERPC invalid bind attempt` to port 135.
- `dcerpc` events: **31** BIND requests, 23 with no interface UUID and 8 with random UUIDs; all `response:"UNREPLIED"`.
- Interpretation: malformed/random DCE/RPC binds are being sprayed at the endpoint mapper — exploit/recon behaviour, likely unsuccessful (no successful bind response observed).

### 3.4 FTP weak-password login success — brute force succeeded
- Filter: `ftp` events where `(src=175.45.176.1, dst=149.171.126.19, dport=21)`:
  - **59 ×** `USER` → **59 ×** `PASS password` → **59 ×** reply `230 Login successful.`
- The same attacker also hit **149.171.126.10:21**:
  - **49 ×** `PASS password` → `Login successful`
  - **1 ×** anonymous login followed by `RETR /../../../../../1WcQaXh/YlcoTbfJes.NCu` (1,663 bytes downloaded)
- Stock rules only flagged the **USER overflow/fuzz strings** (SIDs 2101734, 2011487, 2011488); **no stock rule flagged the successful weak-password logins or the file download**.

### 3.5 MySQL root brute force / scan
- Filter: `flow` where `(src=175.45.176.1, dst=149.171.126.17, dport=3306)` → **128** short connections, nearly all ~768 B in / ~806 B out, closed.
- Alerts: **19** `ET SCAN Suspicious inbound to mySQL port 3306` + **4** `ET SCAN MYSQL 4.1 brute force root login attempt`.
- No MySQL app-layer parser data is available; the equal-sized closed flows suggest rejected login attempts (likely unsuccessful).

### 3.6 Broad multi-vector recon/fuzzing (all four attacker IPs)
- RPC portmap requests (TCP/UDP 111) across 149.171.126.10–.19 — dozens of signatures, low counts each.
- 175.45.176.0: TFTP `Put` / `GET Admin.dll`, SNMP public access, PostgreSQL 5432 and Oracle 1521 scans, **SQL Slammer worm propagation** to 149.171.126.17:1434/UDP, SMB IPC$ to .15.
- 175.45.176.3: DNS zone transfer attempts to .15:53, SMB IPC$ on multiple hosts.
- 175.45.176.2: `SURICATA HTTP request buffer too long` ×28 to .10:80 at ~1/sec (oversized-request flood), Bindshell2 shellcode (UDP) to .18:36782, SMB Trans2 pool-overflow attempt.
- Web attacks across the range: SQLi (`UNION SELECT`, `INSERT INTO`, `INTO OUTFILE`, `exec`), XSS, `/etc/hosts`, `/etc/shadow`, `administrators.pwd`, `.cnf`, `.htr`, XXE, RFI — mostly single/few attempts, no evidence of success.

### 3.7 Stale Heartbleed custom rules — false positives here
- `7600102`/`7600103` fired 34/32 times, but the only relevant flow is:
  - 175.45.176.0 → 149.171.126.18:2444: **217,746 B up / 3,576 B down**.
- That is a **large upload to a TLS service**, the opposite of a Heartbleed leak (small request → huge response), and there was **no** `invalid_encrypted_heartbeat` app-layer event. These are CIC-IDS2017 leftovers that do not apply to UNSW.

Wrote `rules/generated/unsw_triage.rules` and validated against `data/pcaps/unsw/3.pcap` (`logs/unsw-3-triage-validate/`):

All three rules loaded cleanly (no parse errors) and fired on the intended true-positive behaviour.

## 5. Proposed suppressions (awaiting approval — not applied)

These are proposed for the UNSW suppress file (`config/threshold-unsw.config`, currently empty). I did **not** write them.

## 6. Coverage gaps identified

1. **FTP successful weak-password login was invisible** — stock only alerted on USER fuzz strings. *(Closed by SID 7600201.)*
2. **FTP data staging/exfil (RETR/STOR) not alerted** — the anonymous `RETR` of a 1,663-byte file and several uploads to .10 went undetected. A reliable rule would need FTP command/file-name modelling; left unmodelled.
3. **POP3 mailbox exfiltration not alerted** — .13 sent ~1.16 MB total to the attacker over two POP3 sessions; no `pop3` app-layer events were generated (parser gap) and no stock rule fired on the flows.
4. **DCERPC invalid-bind flood is only reported per-bind** — 69 individual alerts rather than one campaign-level alert. A thresholded `dcerpc` rule would consolidate it, but Suricata 8.0.6 rejected `dcerpc.iface` in the existing generated ruleset, so this needs a supported-keyword approach.
5. **SMB IPC$ burst was per-session noise** — stock fired 124 times for one campaign. *(Consolidated by SID 7600202.)*
6. **Stale cross-dataset custom rules** (7600102/7600103) generated 66 misleading alerts in this capture. *(Suppression proposed.)*
