## 4. Actions taken / proposed

### Written (validated) — rules/generated/unsw/rounds_research.rules
Confirmed FTP directory-traversal file retrieval had **no deployed signature** (`search_rules` found none for FTP traversal). I wrote:

```
alert tcp $EXTERNAL_NET any -> $HOME_NET $FTP_PORTS (msg:"UNSW FTP directory traversal file retrieval (RETR ../)"; flow:to_server,established; content:"RETR"; nocase; content:"../"; distance:0; within:64; classtype:attempted-recon; sid:1100001; rev:1;)
alert tcp $EXTERNAL_NET any -> $HOME_NET $FTP_PORTS (msg:"UNSW FTP directory traversal file size check (SIZE ../)"; flow:to_server,established; content:"SIZE"; nocase; content:"../"; distance:0; within:64; classtype:attempted-recon; sid:1100002; rev:1;)
```

Validated by re-running Suricata on `data/pcaps/unsw/3.pcap`: **sid 1100001 fired 34 times, sid 1100002 fired 34 times** — exactly matching the confirmed traversal commands.

### Proposed (NOT written — awaiting approval) — threshold.config
The `SERVER-OTHER BGP spoofed connection reset attempt` signature (sid 2523) produced 1,422 alerts, but **all** port-179 flows are `state=closed` (848 closed / 1 new) and there is no established BGP session anywhere in the capture. The signature is firing on both directions of ordinary RSTs generated by the attacker's port-179 scan — not on a real BGP session reset/hijack. Proposed:

```
# SID 2523 "SERVER-OTHER BGP spoofed connection reset attempt" — 1,422 alerts.
# All port-179 flows in this capture are state=closed (no established BGP session);
# the signature fires on RSTs from the attacker's port-179 scan, not a real BGP reset.
suppress gen_id 1, sig_id 2523
```

If you prefer to keep the signature live for real BGP networks, a scoped alternative would be to suppress only for the attacker range (and its RST responders), but a global suppress is cleanest for this research baseline.

## 5. Coverage gaps identified

1. **FTP directory traversal (RETR/SIZE `../`)** — was undetected despite confirmed successful exfiltration. **Now covered** by sid 1100001/1100002.
2. **iSCSI port 3260** — 458 uniform probe flows (.3→.15) with **no app-layer parse and no detection rule** (`search_rules` returned no iSCSI signature). Needs packet-level analysis to determine whether it is a login brute-force, an iSCSI PDU exploit, or pure recon.
3. **BGP port-179 scan** — detected only via a mis-firing "spoofed reset" signature (see §4); the actual scan itself is not cleanly modelled.
4. **MySQL brute force** — only 4 alerts against 128 closed MySQL flows; the deployed rule catches a narrow root-login pattern, leaving the wider MySQL probing largely unmodelled.
5. **Automated web tooling** (463 randomised-UA POSTs to one path in a single flow) — captured only indirectly via shellcode/HTTP parser alerts; no signature identifies the tool behaviour itself.

**Bottom line:** This capture is a genuine, partially successful attack campaign — FTP was compromised (anonymous access + directory-traversal exfiltration), and SMB, SMTP, HTTP, MySQL, RPC and iSCSI were all probed or attacked. The single most valuable new detection (FTP traversal) is now deployed; the largest noise source (BGP "spoofed reset") has a suppress proposal awaiting your approval.
