## 3. Confirmed attacks (deep dive)

### 3.1 Shellcode attack against SMTP/HTTP/SMB (SID 1394)
- Top flow: `175.45.176.3:18874 -> 149.171.126.17:25` (SMTP).
- That single flow pushed **7,304,693 bytes to the server in 5,422 packets**, with 49,240 bytes returned.
- Suricata did not parse it as SMTP (`app_proto: null`) because the stream hit `stream_reassembly_memcap`; the payload is a raw NOOP-sled shellcode flood.
- This is a genuine exploit/shellcode attack, and the baseline shellcode rules already detect it (albeit noisily).

### 3.2 BGP spoofed connection reset / BGP DoS (SID 2523)
- Repeated short TCP flows from `175.45.176.0/24` to internal **port 179** on multiple hosts, especially `149.171.126.19`.
- Flows are highly regular (`pkts_toserver 10`, `bytes_toserver 694`), consistent with automated BGP reset/DoS traffic.
- Alerts fire in both directions (726 `to_client`, 678 `to_server`).
- Verdict: **true attack pattern**, but the community rule is noisy (1,404 alerts). I did **not** suppress it; I recommend a threshold instead of a suppress if volume becomes an issue.

### 3.3 FTP compromise and fuzzing
Scoped queries:
- `GPL FTP anonymous login attempt`: `175.45.176.1 -> 149.171.126.10` (150) and other attacker pairs — 224 total.
- `UNSW FTP successful login from external host` (SID 1000004): 112 alerts. The largest pairs are:
  - `149.171.126.19 -> 175.45.176.1` (59) — i.e. attacker `.1` logged into FTP server `.19`
  - `149.171.126.10 -> 175.45.176.1` (49)
- After login, the attacker:
  - sends repeated `PORT` commands with oversized decimal octets (`4294967296`, `2147483648`, …) — covered by SID 1000001;
  - issues **`RETR /../../../../../...` path-traversal file reads** — 25 such FTP events from attacker IPs to internal FTP servers. One example from `175.45.176.1 -> 149.171.126.10`:
    - `SIZE /../../../../../1WcQaXh/YlcoTbfJes.NCu` → `213 1663`
    - `RETR /../../../../../1WcQaXh/YlcoTbfJes.NCu` → `150`/`226` (**transfer completed**).

The FTP path traversal was **not covered** by any loaded rule.

### 3.4 POP3 mailbox compromise and exfiltration
- `UNSW POP3 successful login from external host` (SID 1000003): 71 alerts across many attacker→server pairs.
- POP3 app-layer events confirm the attacker logs in (`USER`/`PASS` → `logged in.`), then runs `LIST`, `UIDL`, and **`RETR 1`**.
- Scoped count: **36 `POP3 RETR` commands** from `175.45.176.0/24` to internal POP3 servers (top: `.3 -> .18` = 7, `.0 -> .12` = 4).
- The login was already covered by SID 1000003, but **the RETR exfiltration itself was not covered**.

### 3.5 SMB / DCERPC
- `GPL NETBIOS SMB-DS IPC$ unicode share access` (SID 2102466): **124 alerts from `175.45.176.1 -> 149.171.126.15`** plus smaller pairs.
- SMB events show 58 `NEGOTIATE_PROTOCOL` and 58 `TREE_CONNECT_ANDX` from `.1 -> .15` — share enumeration.
- `GPL NETBIOS DCERPC invalid bind attempt` (SID 2102190): **69 alerts, all `175.45.176.2 -> 149.171.126.18`** — random UUID BIND requests, endpoint scanning/fuzzing.
- Both are covered by the baseline.

### 3.6 Web application attacks
- Many ET/GPL web rules fired from the attacker range against internal web servers: PHP RFI, SQLi (`UNION SELECT`, `INSERT INTO`, `INTO OUTFILE`), XSS, XML-RPC PHP RCE, Mambo/Joomla RFI, ColdFusion access, Cisco IOS HTTP config, `/doc/` access, etc.
- These are true positives and are already covered by the baseline.

### 3.7 DNS attacks
Scoped to attacker sources:
- **`www.exa.dpn` ANY flood**: **2,572 DNS requests from `175.45.176.0 -> 149.171.126.12`**, all identical `ANY` queries; the server responded `NXDOMAIN` 2,568 times. This flood was **not covered** by any loaded DNS rule.
- DNS dynamic update (opcode 5): covered by existing generated SID 1000002.
- `VERSION.BIND` / `AUTHORS.BIND` queries: covered by `GPL DNS named version attempt` / `named authors attempt`.
- Zone transfer attempts: covered by `GPL DNS zone transfer TCP/UDP`.

### 3.8 LDAP SASL bind / oversized credentials
- LDAP events show:
  - `175.45.176.3 -> 149.171.126.13` — anonymous bind (`name:""`) with **success**.
  - `175.45.176.2 -> 149.171.126.11` — **SASL `CRAM-MD5` bind with a massive space-filled credential blob** (thousands of `0x20` bytes), followed by `sasl_bind_in_progress`.
- No loaded LDAP rule covered this; it looks like an LDAP fuzz/overflow probe.

### 3.9 Other recon/fuzz
- IP protocol scan: `175.45.176.0 -> 149.171.126.13` sends packets using every IP protocol number — covered by SID 2101627.
- MySQL scan / `MYSQL 4.1 brute force root login`: covered by SIDs 2010937 / 2002842.
- TFTP `GET Admin.dll` and long-filename PUT/GET: covered by baseline TFTP rules.
- SIP INVITE flood (`175.45.176.1 -> 149.171.126.18`, 300 INVITEs): covered by `ET VOIP INVITE Message Flood UDP` and `GPL VOIP SIP INVITE message flooding`.

## 4. Actions taken — new detection rules

I appended four rules to `rules/generated/unsw/rounds_plain.rules` (the only generated file loaded for validation):

| SID | Rule | Covers |
|---|---|---|
| 1000006 | FTP path traversal command from external host (`content:"/../"`) | 25 uncovered FTP `RETR /../` events |
| 1000007 | POP3 RETR mailbox exfiltration from external host | 36 uncovered POP3 `RETR` events |
| 1000008 | DNS ANY query flood for `www.exa.dpn` from external host (with `threshold: limit, by_src, 20/60s`) | 2,572 uncovered DNS flood queries |
| 1000009 | LDAP SASL CRAM-MD5 bind attempt from external host | 2 uncovered LDAP SASL bind events |

I then re-ran Suricata on `data/pcaps/unsw/3.pcap` to validate. The rules parsed and fired:
- 1000006 → 36 alerts
- 1000007 → 64 alerts
- 1000008 → 520 alerts (threshold limited from 2,572)
- 1000009 → 2 alerts

## 5. Proposed suppressions (NOT applied — awaiting approval)

These are parser/capture artifacts on **internal, legitimate** traffic:

```
# Internal HTTP keep-alive/pipelining; Suricata cannot match every response to a request
suppress gen_id 1, sig_id 2221010

# Internal HTTP clients send non-compliant URI characters; parser noise, not an attack
suppress gen_id 1, sig_id 2221029

# MQTT capture starts mid-session; messages appear before CONNECT/CONNACK
suppress gen_id 1, sig_id 2229005
```

I did **not** propose suppressing the BGP rule (2523) or the stream "out of window" rule (2210020), because those are consistent with real attack traffic in this capture.

## 6. Coverage gaps identified

1. **FTP path traversal** — was invisible; now covered by SID 1000006.
2. **POP3 RETR mailbox exfiltration** — was invisible; now covered by SID 1000007.
3. **DNS ANY query flood** — was invisible; now covered by SID 1000008.
4. **LDAP SASL CRAM-MD5 oversized bind** — was invisible; now covered by SID 1000009.
5. **External IKEv1 negotiation** — `175.45.176.0 -> 149.171.126.13` completed an IKEv1 exchange (3DES/SHA1/Group2). The loaded IKE weak-crypto engine rules did **not** fire on it, so external-to-internal VPN/IKE negotiation remains a monitoring gap. I did not write a rule because I could not confirm the exact Suricata IKE keyword syntax against the loaded rule set in the time available; recommend a follow-up.
6. **BGP reset DoS rule fidelity** — SID 2523 detects the activity but emits 1,404 alerts; a `threshold` line (rather than a suppress) would make it operationally useful.
