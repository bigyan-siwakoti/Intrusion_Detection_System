## 4. Actions taken

### New detection rules written to `rules/generated/unsw_bare.rules`
Appended three campaign-level rules:

| SID | Rule | Rationale |
|---|---|---|
| `7700008` | Slow RPC portmap sweep, count 20/1800s by_src | Stock GPL only fires per RPC program. Existing `7700002` (30/120s) is too high for this low-and-slow sweep (peak 8 queries/min per source). |
| `7700009` | Slow SMB IPC$ share-access sweep, count 5/1800s by_src on `[139,445]` | Stock fires per connection. Existing `7700001` (20/60s) misses this 2-per-minute distributed sweep. |
| `7700010` | SSH brute-force campaign, count 10/3600s by_src | `9500002` caught it in this run, but that rule lives in another generated file; `unsw_bare.rules` is the only generated file loaded for UNSW validation. |

### Proposed suppression (NOT applied — requires engineer approval)
```
# logs/unsw-10-bare/eve.json: all 80 instances are HOME_NET server -> HOME_NET client
# (149.171.126.x -> 59.166.0.x) TCP stream events from normal internal HTTP
# responses; mid-capture/segment artifact, not attacker traffic.
suppress gen_id 1, sig_id 2210020
```

I deliberately did **not** propose suppressing the other noisy stream events (`2210029`, `2210045`, `2221029`, `2221010`) because they also contain attacker-sourced instances, and a global suppress would hide potentially relevant attack traffic.

## 5. Coverage gaps identified

1. **Low-and-slow distributed sweeps** — the stock ruleset reports RPC portmap and SMB IPC$ activity only as per-program/per-connection alerts. No source-level campaign alert existed for the observed rates. Addressed with `7700008`/`7700009`.
2. **SSH campaign rule absent from `unsw_bare.rules`** — the campaign was detected here only because another generated file was present in this run. Addressed with `7700010`.
3. **Heartbleed overflow confirmation** — only the recon-precursor rules fired; the actual out-of-bounds heartbeat leak was not confirmed by any alert. `unsw_bare.rules` already has `7700003` (`tls.overflow_heartbeat`), but stock/ET heartbeat-payload coverage is unreliable for encrypted heartbeats. If the pcap is re-run, `7700003` should be the success indicator.
4. **Web attack spray correlation** — dozens of distinct web exploit signatures fire one-per-attempt, but nothing correlates them into a single "attacker spraying exploits at HOME_NET web servers" picture. A future high-fidelity rule could threshold distinct attacker→HOME_NET HTTP exploit traffic, but care is needed to avoid false positives from legitimate external web traffic.
